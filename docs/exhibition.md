# 展示・運用

## 実行環境

| 処理 | 実行場所 |
| --- | --- |
| 複素振幅、コイン、移動、位相 | ブラウザー内のCPU |
| 波の色・明るさ、花の候補、流線データ | ブラウザー内のCPU |
| 発光、花弁、残光、最終描画 | WebGL 2によるGPU |
| 音 | Web Audio API |

ビルドにはNode.js 22.12以降を使用します。作品の実行には、WebGL 2対応のブラウザーと静的ファイルを配信する環境を使います。外部APIや量子クラウドへの接続は現在の実装に含めていません。

## 計算資源の目安

- 一つの場：`161 × 161 × 2 = 51,842`個の複素振幅
- 実部・虚部をFloat32で保持：一つの場あたり414,736 bytes（約0.40 MiB）
- 主要なCPU数値バッファ：約`2.9 + 0.40K` MiB（`K`は活動中のタネの数）
- 計算量：格子数と活動中のタネの数におおむね比例

上記は数値配列から積算した値です。ブラウザー本体、オブジェクト、GPU資源などの使用量は別途加わります。タネの数には固定の上限を設けておらず、短時間に多く入力するとCPU負荷と使用メモリが増えます。

残光用の主なGPUテクスチャはRGBA8を2枚使うため、描画バッファの幅`W`・高さ`H`に対して約`8WH` bytesです。1920×1080なら約15.8 MiB、3840×2160なら約63.3 MiBとなります。画面のデバイスピクセル比は最大1.35まで反映します。これもGPU全体の使用量ではなく、残光テクスチャ部分の見積もりです。

実行速度はCPU、GPU、解像度、同時入力数で変わります。目標は185 msごとの量子ステップと最大60 fpsの描画です。最終的な展示機器で確認してください。

### 将来の量子実機への接続

位置レジスタとして符号化する場合、xに8量子ビット、yに8量子ビット、コインに1量子ビットを割り当てると、計17量子ビットに状態を収められます。補助量子ビットや測定に必要な資源は別途検討します。

実機化には、タネの状態準備、161を法とする移動、位置依存位相の回路化、描画へ渡すデータの読み出しを設計する必要があります。17量子ビットという数は符号化容量の目安であり、そのまま展示速度や回路規模を保証する数値ではありません。

## 本番用の確認

```sh
npm ci
npm run check
npm run preview
```

[localhost:4174](http://localhost:4174/) で本番ビルドを確認できます。`npm run preview`はローカル確認用です。展示では`dist/`を適切な静的サーバーから配信してください。サブディレクトリに配信する場合は、配信先に合わせてViteの`base`を指定します。

現在、このリポジトリに自動公開の処理は設定していません。GitHub Actionsはテストとビルドを行います。

## 展示前チェック

- 起動時にタイトルが表示され、タップで消える
- 次のタップで選んだ場所にタネが置かれる
- 三つ以上のタネを置いても、以前の波の光量が維持される
- 各波が自身の100ステップ後から薄くなる
- ドラッグと長押しが、想定した入力として動く
- `F`で全画面化でき、タッチの位置が表示と一致する
- 音量を調整し、必要に応じて`M`でミュートする
- 想定する最大入力数・解像度で連続運転を確認する
- ブラウザーのバックグラウンド化と復帰を確認する
- スリープや画面消灯の設定を、展示担当者が確認する

量子ステップはタブが表示されている間に進みます。別のタブへ移ると進行を休止し、戻った際に休止時間分をまとめて計算する処理は行いません。リロードすると作品は初期状態へ戻ります。

## 問題が起きたとき

| 状況 | 確認する点 |
| --- | --- |
| タイトル後に暗い画面が続く | 好きな場所をもう一度タップしてタネを置く |
| WebGL 2のエラーが出る | ブラウザーとGPU設定、ハードウェアアクセラレーション |
| 音が出ない | 作品画面をタップしたか、`M`やOS側のミュート状態 |
| 動きが重い | 解像度と同時に置いたタネの数。必要なら`R`でリセット |
| 開発サーバーが起動しない | Node.jsのバージョンと、5174番ポートの使用状況 |

権限設定、スリープ設定、公開範囲などの環境変更は、運用担当者の判断で行ってください。
